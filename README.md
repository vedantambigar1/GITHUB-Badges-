## 🧭 Overview
 
Shortcuts like dummy accounts, star swaps, or spammy PRs get flagged by GitHub's anti-abuse systems and can lead to removed stars, withheld achievements, or account restrictions. This guide shows how to earn every badge through real projects, real contributions, and real collaboration.
 
> [!NOTE]
> GitHub occasionally changes achievement names, tiers, and thresholds. Verify at `github.com/<username>?tab=achievements`. Tier numbers below are the commonly documented values at the time of writing.

## 📖 Detailed Guides
 
<details open>
<summary><h3>⭐ Starstruck</h3></summary>
**Goal:** Get stars on a single public repository you own.
 
**How to earn it organically**
- **Solve a real pain point.** CLI tools, small libraries, config boilerplates, templates, cheat-sheets.
- **Write a stellar README.** Install steps, usage examples, code snippets, screenshots or a GIF demo. Documentation is the biggest driver of organic stars.
- **Share where developers hang out.** Relevant subreddits, Discord/Slack communities, dev.to, Hashnode, Show HN, LinkedIn, only where self-promotion is allowed.
- **Make it discoverable.** Add a description, topics, a license, and a social preview image.
- **Keep it maintained.** Answer issues, tag releases, keep a changelog.
**Avoid:** star-for-star swaps, bot networks, and alt accounts. Those stars get removed.
</details>
<details>
<summary><h3>🦈 Pull Shark</h3></summary>
**Goal:** Have pull requests merged.
 
- Start with beginner-friendly repos such as [first-contributions](https://github.com/firstcontributions/first-contributions).
- Fix typos, improve docs, add missing examples, ship small bug fixes in libraries you use.
- Look for issues labelled `good first issue` or `help wanted`.
- Keep PRs small, focused, and well described so they merge faster.
</details>
<details>
<summary><h3>⚡ Quickdraw</h3></summary>
**Goal:** Close an issue or pull request within 5 minutes of opening it.
 
- In your own repo, open an issue or PR for a tiny fix (a typo, for instance) and close or merge it right away.
- It's a one-time badge, so there's no need to repeat it.
</details>
<details>
<summary><h3>🎲 YOLO</h3></summary>
**Goal:** Merge a pull request without a code review.
 
- In a personal repo where you're the sole maintainer, open a PR from a branch and merge it into `main` without requesting review.
- Branch protection rules requiring reviews must be off.
- Fine for side projects; keep review rules on in team repos.
</details>
<details>
<summary><h3>👯 Pair Extraordinaire</h3></summary>
**Goal:** Get a PR merged that contains co-authored commits.
 
```bash
git commit -m "feat: add authentication middleware
 
Co-authored-by: Partner Name <partner@email.com>"
```
 
- Use the email linked to your partner's GitHub account so they get credit.
- When the PR merges, the badge unlocks for both of you.
</details>
<details>
<summary><h3>🧠 Galaxy Brain</h3></summary>
**Goal:** Have your answers accepted in GitHub Discussions.
 
- Browse Discussions on popular repos and answer Q&A questions in tools you know well.
- Include code samples and links to docs.
- Only answers marked accepted by the asker or a maintainer count.
</details>
<details>
<summary><h3>💖 Public Sponsor</h3></summary>
**Goal:** Sponsor an open-source maintainer or project through GitHub Sponsors.
 
- Even a small monthly or one-time amount works.
- Keep the sponsorship public so it appears on your profile.
</details>
<details>
<summary><h3>🧑‍🚀 Open Sourcerer</h3></summary>
**Goal:** Have PRs merged across multiple public repositories.
 
- Spread small, useful PRs across different projects instead of many in one.
- Rotate through tools you actually use: linters, frameworks, docs sites, CLIs.
- Check current requirements on your Achievements page, as thresholds may change.
</details>
<details>
<summary><h3>💙 Heart On Your Sleeve</h3></summary>
**Goal:** React with ❤️ to others' issues, PRs, comments, and discussions.
 
- Genuinely appreciate helpful contributions and react when something helps you.
</details>
<details>
<summary><h3>🌟 Highlight</h3></summary>
**Goal:** Have a contribution featured in a GitHub Highlight.
 
- Publish something notable: a well-documented project, a technical write-up, a community-valued contribution.
- Largely at GitHub's discretion, so treat it as a bonus.
</details>
<details>
<summary><h3>🛠️ Developer Program Member</h3></summary>
**Goal:** Join the GitHub Developer Program.
 
- Register if you build apps or integrations on the GitHub platform.
- Build something with the GitHub API or Apps platform to make it meaningful.
</details>
<details>
<summary><h3>💎 GitHub Pro</h3></summary>
**Goal:** Hold a GitHub Pro subscription.
 
- Subscribe to the Pro plan.
- Students and educators can often get it free via the GitHub Student Developer Pack or GitHub Education.
</details>
<details>
<summary><h3>❄️ Arctic Code Vault Contributor (retired)</h3></summary>
Awarded to developers whose public code was in the GitHub Archive Program snapshot of **February 2, 2020**, stored in an Arctic vault. It cannot be earned anymore.
</details>
<details>
<summary><h3>🚁 Mars 2020 Helicopter Contributor (retired)</h3></summary>
Awarded to contributors to open-source projects used by NASA's Ingenuity helicopter on the Mars 2020 mission. It cannot be earned anymore.
</details>

## ✅ Dos & Don'ts
 
| ✅ Do | 🚫 Don't |
|---|---|
| Keep repos public so activity registers | Create alt accounts to star your own repos |
| Contribute consistently over time | Join star-for-star or follow-for-follow groups |
| Pin your best repos and write a profile README | Open trivial or spammy PRs to inflate counts |
| Build tools you genuinely use | Buy stars or followers |
| Review and react to others' work | Chase badges at the cost of quality |
 
Violations of GitHub's Terms and Acceptable Use Policies can lead to removal of achievements or account suspension.
